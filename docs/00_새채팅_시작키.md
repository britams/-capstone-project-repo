**2. 읽기 (순서대로, 다 읽기 전엔 작업 시작하지 말 것)**

2. `docs/*_분업계획_서현_승준.md` 중 가장 최근 것 — **내 역할과 내가 편집하는 파일** (승준이면 `docs/*_승준_작업지시.md` 최신 것도 — 지금 할 일 J1~J7)

내 로그의 마지막 항목에서 멈춘 지점부터 이어서 해. 먼저 "어디까지 됐고, 이번에 무엇부터 할지, 정해야 할 것"을 짧게 말하고 시작해.

**4. 작업 규칙**
- 동의로 시작하지 말고, 첫 문장에서 가정의 허점이나 놓친 점을 짚어.
- 주장 앞에 [확실] / [가능성 높음] / [추측]을 붙여. 확실하지 않은 건 추측으로 진행하지 말고 먼저 물어봐.
- 중요한 답부터, 서론 없이.
- **분업계획에서 내 담당이 아닌 파일은 고치지 마.** 고칠 게 있으면 알려 주거나 레포 Issues에 적게 해. `design/인터페이스_정의서.md`를 바꾸면 변경 이력에 날짜·이름·이유를 적어.
- FreeCAD는 MCP로 다루고(서현 PC), **모델은 Python 생성 스크립트(`cad/*.py`)로 만들어 함께 저장해** (.FCStd는 Git으로 병합이 안 됨). 치수는 설계 변수표에서 읽게 해. FreeCAD가 응답이 없으면 켜고 MCP 애드온을 실행하라고 말해.
- **인수인계는 `docs/00_새채팅_인수인계_*.md` 한 개만 유지**: 갱신할 땐 내용을 고치고 파일명 날짜를 바꿔 (이전 버전은 Git 기록에 남음). 설계 회차 문서(`design/`)는 수업 규칙대로 날짜별 새 파일로 누적하고 지우지 않아.
- 레포에 올리면 안 되는 것: 논문 PDF, 전화번호·학번이 든 파일, 25 MB 넘는 파일 (`docs/GitHub_사용법_Chrome.md` 7장).
- 설계값·문장·도면부호에 AI 결과를 반영하면 로그 번호(서현 `CAP-AI-nn`, 승준 `CAP-AI-SJ-nn`)를 붙이고, 검증 못 한 값은 `미검증`.
- **세션 끝나기 전에 반드시** 내 AI 로그 맨 아래에 새 항목(날짜·명령·한 일·만든 파일·검증·남은 결정)을 추가하고, 레포에 올라가게 해 (직접 push 또는 내가 올릴 파일 목록 안내). 팀 상태가 크게 바뀌었으면 (서현만) 인수인계 파일을 갱신해.
- 사용량이 거의 다 됐다고 하면, 즉시 위 파일들을 갱신해서 다음 채팅이 이 키로 이어갈 수 있게 해.
