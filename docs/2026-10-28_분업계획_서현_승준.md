## 1. 원칙

1. **기구(서현) ↔ 비전·전자(승준)로 나눈다.** 두 영역이 만나는 곳은 `design/인터페이스_정의서.md` 한 파일로만 맞춘다. [가능성 높음] 두 영역은 인터페이스만 정해지면 동시에 진행할 수 있어 2인 팀에 가장 효율적이다.
2. **개념 선정(D3·D4)과 표본 채집은 같이 한다.** 구조를 고르는 결정에 둘 다 참여해야 나중에 뒤집히지 않는다.
3. **파일마다 담당자 1명.** 남의 파일은 고치지 않는다. 고칠 게 있으면 그 사람에게 말하거나, 자기 이름으로 새 날짜 파일을 만든다 (공유 폴더 동기화 충돌 방지).
4. **각자 자기 Claude로 작업하고, AI 로그는 각자 파일에 남긴다.** 둘 다 `docs/00_새채팅_시작키.md`로 새 채팅을 시작한다 (키 안에 이름을 넣는 줄이 있음).
5. **공유 문서의 원본은 GitHub 레포.** 서현 PC 폴더는 논문·PPT·사진·FreeCAD 작업 보관용이다.

- [확실] 지금 가진 「야생 말벌 포획기」는 흑등(등검은)말벌을 잡는 제품이다. 설명서상 포획통을 냉동실에 약 5분 넣으면 기절한다.
- [가능성 높음] 등검은말벌은 11월까지 활동하고 그 뒤엔 봄까지 구하기 어렵다 (10/26 보고, 농촌진흥청 장기 조사 인용). **이번 주에 설치하지 않으면 표본 없이 설계 치수를 정해야 한다.**
- 경로 후보: ① 보유 트랩을 양봉장·산 근처에 설치 ② 최문보 교수님께 표본 요청 ③ 근처 양봉농가에 트랩에 잡힌 말벌 요청
- 안전: 살아 있는 말벌이 든 포획통은 목·바닥만 잡고(설명서), 보호 장갑 착용, 냉동 후 취급

## 6. Claude · GitHub 사용 방법 (둘 다)

- 새 채팅 시작: 레포 `docs/00_새채팅_시작키.md`의 `---` 사이를 붙여 넣고, 첫 줄의 이름을 자기 이름으로.
- **Claude에 GitHub를 연결하면** Claude가 레포를 직접 읽고 commit·push 한다 → 사람은 Chrome에서 확인만. 각자 자기 Claude에서 자기 GitHub 계정으로 연결 (승준은 레포 초대를 먼저 수락).
- **연결 안 했을 때**: Claude가 레포와 같은 폴더 구조로 파일을 만들어 주면 Chrome에서 **Add file → Upload files**로 올린다.
- 세션 끝: 자기 AI 로그 맨 아래에 항목 추가(서현 `CAP-AI-nn`, 승준 `CAP-AI-SJ-nn`) → 레포에 올라갔는지 Chrome에서 확인.
- AI 결과를 설계값·도면부호에 쓰면 그 자리에 로그 번호를 붙이고, 검증 못 한 값은 `미검증`.
- FreeCAD 모델은 Python 생성 스크립트(`cad/*.py`)와 함께 올린다 (.FCStd는 Git으로 병합이 안 되고, 서현만 편집).
