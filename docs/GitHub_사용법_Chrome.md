# GitHub 사용법 — Chrome만으로 (설치 없음)

대상: 팀 초벌 (이서현·이승준) · 정리일: 2026-10-28
레포: https://github.com/britams/-capstone-project-repo

> 이 레포가 **공유 문서의 원본**이다. 인수인계·분업계획·AI 로그·설계 문서·코드는 여기 있는 것이 최신이다.
> 논문 PDF, 큰 PPT, 사진 원본은 올리지 않는다 (7장).

---

## 0. 처음 한 번만

**승준**
1. https://github.com/signup 에서 계정을 만든다 (이메일·비밀번호·사용자 이름).
2. 사용자 이름을 서현에게 알려 준다.
3. 메일함(또는 GitHub 오른쪽 위 알림)에서 레포 초대를 **Accept** 한다.

**서현**
1. 레포 → **Settings** → 왼쪽 **Collaborators** → **Add people** → 승준 사용자 이름 입력 → 초대. (10/28 완료)
2. 레포는 **공개(Public)로 운영**한다 (서현 결정 10/28). 그래서 7장의 '올리면 안 되는 것'을 꼭 지킨다.

## 1. 파일 보기
- 레포 주소로 들어가 폴더·파일 이름을 누른다. md 파일은 표·제목이 정리된 모양으로 보인다.
- 오른쪽 위 **History**(시계 아이콘)를 누르면 누가 언제 무엇을 바꿨는지 보인다.

## 2. 파일 고치기 (md 같은 글 파일)
1. 파일을 연다 → 오른쪽 위 **연필 아이콘(Edit this file)**.
2. 고친다. **Preview** 탭으로 모양을 확인할 수 있다.
3. 오른쪽 위 초록 버튼 **Commit changes...**
4. 메시지에 무엇을 했는지 쓴다. 형식: `[승준] VespAI 실행 결과 추가`
5. **Commit directly to the main branch** 선택 → **Commit changes**.

## 3. 파일 올리기 (Claude가 만든 파일, 코드, 사진 등)
1. 올릴 폴더로 들어간다 (예: `vision`).
2. **Add file** → **Upload files**.
3. 파일이나 폴더를 끌어다 놓는다 (Chrome은 폴더째 가능).
4. 메시지를 쓰고 **Commit changes**.
- 같은 이름의 파일이 있으면 **덮어쓴다.** 내 담당이 아닌 파일을 덮어쓰지 않도록 주의.
- 브라우저 업로드는 **파일 하나당 25 MB까지**.

## 4. 새 파일·새 폴더 만들기
- **Add file** → **Create new file**.
- 폴더를 만들려면 파일 이름 칸에 `폴더이름/파일이름.md` 처럼 `/`를 넣는다 (빈 폴더는 만들 수 없음).

## 5. 내려받기
- 파일 하나: 파일을 열고 오른쪽 위 **Download raw file**(↓ 아이콘).
- 전체: 레포 첫 화면 초록 **Code** 버튼 → **Download ZIP**.

## 6. Claude와 같이 쓰기
- **연결 방법 (각자 한 번)**: claude.ai 설정 → Connectors에서 GitHub 연결 → 이 레포에 Claude GitHub 앱 권한이 있어야 Claude가 push 할 수 있다 (레포 주인 서현이 https://github.com/apps/claude/installations/select_target 에서 이 레포를 선택해 설치).
- **연결된 경우**: Claude가 레포를 붙여서 직접 읽고 commit·push 한다. 사람은 Chrome에서 확인만 한다. 레포의 `CLAUDE.md`에 작업 규칙이 있어 Claude가 자동으로 따른다.
- **연결 안 된 경우**:
  - 읽기: 레포가 공개라 Claude가 웹에서 읽을 수 있다. 안 되면 파일을 내려받아 채팅에 첨부한다.
  - 쓰기: Claude가 만든 파일을 내려받아 3장 방법으로 올린다.
- 새 채팅은 `docs/00_새채팅_시작키.md`의 `---` 사이를 붙여 넣어 시작한다.
- 세션이 끝나면 내 AI 로그(`ai-log/`)에 항목이 추가돼 레포에 올라갔는지 Chrome에서 확인한다.

## 7. 올리면 안 되는 것
| 무엇 | 이유 | 대신 둘 곳 |
|---|---|---|
| 논문 PDF | 저작권 (공개 레포면 배포가 됨) | 서현 PC `capstone design_이서현\관련 논문 정리`, 레포엔 서지 정보만 |
| 전화번호·학번이 들어간 파일 (메일 PDF 등) | 개인정보 | 서현 PC |
| 25 MB가 넘는 파일 (작년 발표 PPT 등) | 브라우저 업로드 한도, GitHub 파일 한도 100 MB | 구글 드라이브 등 |
| 사진 원본 (heic) 대량 | 용량 | 필요한 것만 줄여서 |

레포는 공개라서 올린 파일은 누구나 볼 수 있다. 특히 논문 PDF와 개인정보는 올리지 않는다.

## 8. 충돌 막는 규칙
1. 고치기 전에 페이지를 **새로고침**해서 최신 내용을 본다.
2. **내 담당 파일만 고친다** (분업계획 2장). 상대 파일을 고쳐야 하면 말로 알리거나 **Issues**에 적는다.
3. `design/인터페이스_정의서.md`는 둘 다 고칠 수 있다 → 고치면 맨 아래 변경 이력에 날짜·이름·이유를 적는다.
4. 실수로 덮어썼으면 **History**에서 이전 버전을 열어 내용을 복사해 되살린다 (모르면 서현에게).
