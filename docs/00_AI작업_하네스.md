- 클라우드 → PC: 클라우드에서 commit·push → PC에서 `git pull`. 같은 파일을 양쪽에서 동시에 고치지 않는다.
- PC 레포는 `device_bash`에 안 보인다 (마운트 안 됨) → `execute_code`로만 닿는다.
- FreeCAD MCP 애드온 버전 경고 (0.1.27 ↔ 0.1.32)는 무시해도 된다. `execute_code_headless`는 없다 (freecadcmd 없음).

## 4. 작업 루프 — CAD를 한 번 고칠 때
1. 양쪽에서 `git pull`. PC pull은 DNS가 가끔 실패한다 → returncode를 보고, 실패면 몇 초 뒤 다시. **HEAD가 바뀐 것을 확인한 뒤에** 돌린다.
2. 고치는 스크립트 `cad/<이름>.py`: 처음 돌 때 `split/<문서>_before_<이름>.FCStd`로 백업하고, 다시 돌면 백업에서 시작한다 (몇 번 돌려도 같은 결과). 결과는 `split/_<이름>.json` (valid·거리·개수).
3. 돌리기: `Popen([freecad.exe, 스크립트], cwd=cad, creationflags=0x8|0x200|0x08000000)`. 스크립트 끝의 `os._exit(0)` 때문에 **GUI FreeCAD 안에서 exec 하지 않는다.**
4. 결과 json을 읽는다 → 기준을 못 넘으면 고쳐서 2로. 결과가 그럴듯해도, 바뀐 모양을 바깥선·꼭짓점으로 한 번 직접 본다.
5. 전체 수정 + 검사: `Popen([…\bin\python.exe, cad\run_full.py, <이름>, <먼저 돌릴.py …>], cwd=cad)` → 약 45분 → `split/_harness_<이름>.json`이 PASS/FAIL. 기다리는 동안 짧게 자주 묻지 말고, 30~40분 뒤에 확인하도록 예약한다 (send_later).
6. PASS면:
   - PC에서 `git add -u` → commit·push (CAD 결과).
   - 클라우드 문서도 commit·push.
   - PC 사본과 바탕화면을 맞춘다.
   - GUI의 D5g 두 문서를 닫고 다시 연다 (선택 없음, 등각, 화면 맞춤).
7. AI 로그·`cad/README.md`·(필요하면) 인수인계를 고쳐 push → 서현에게 쉬운 설명.

## 6. 안전장치 — 하지 않는 것
- 공개 레포에 올리지 않는 것:
  - 논문·교재 PDF, 문제 원문·그림
  - 전화번호·학번이 든 파일, 25 MB 넘는 파일
  - 말벌 사진, 업체 STEP
  - 영수증·견적서·제품 사진
- 로그인·비밀번호 입력을 하지 않는다 (meviy·미스미·쇼핑몰은 사람이). 주문·결제도 하지 않는다 — 견적·구매는 승준. 계정 이메일을 외부 서비스에 보내지 않는다.
- 화면 조작 (computer use)을 하지 않는다 (서현 "원격 그만"). FreeCAD MCP와 브라우저는 된다.
  - 네이버 쇼핑은 막혀 있다.
  - 봇 검사는 우회하지 않는다.
- 프로세스를 강제로 끄지 않는다 (taskkill 거절됨 — 다른 방법으로 돌려서 하지도 않음). 남은 창은 서현에게 닫아 달라고 한다.
- CAD는 꼭 필요할 때만 연다 (서현 "막 쓰지 말고").
- 서현 PC 파일을 덮어쓰기 전에 세 가지를 본다:
  - md5가 내가 전에 쓴 것과 같은지 (다르면 서현이 고친 것 → 묻기)
  - `~$` 잠금 파일이 없는지
  - `expectedMtimeMs`
- 서현은 자르기·납땜·탭·집 3D 프린트를 하지 않는다 → 판은 업체 (탭·접시도 업체), 프린트는 학교.
- `design/인터페이스_정의서.md`를 바꾸면 변경 이력을 남긴다. 날짜 붙은 회차 문서는 고치지 않는다.
- 원격 호출 한 번은 80초가 넘으면 끊긴다 → `execute_code` 안에서 기다리는 루프는 60초 안쪽으로.
