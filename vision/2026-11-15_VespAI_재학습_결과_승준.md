## 1. 왜 다시 학습했나
- VespAI 원래 가중치(`yolov5s-all-data.pt`)가 우리 촬영 조건에서 기대보다 못 맞힘 (10/29 프린트 시험 79 %, 승준 11/12 판단 "생각보다 효과가 없음")
- 그래서 우리 표본을 우리 조건으로 찍어 VespAI 가중치에서 이어서 학습함 (처음부터 학습 아님)

## 2. 조건
- 촬영: 알코올 표본(등검은말벌), 위에서 아래로, 바닥 흰 종이, 높이 약 10~20 cm, 웹캠 녹화 → Roboflow에서 1초 2장 잘라 네모 라벨
- 클래스: `velutina`, `other` (Roboflow 알파벳 순 → 0 other, 1 velutina — VespAI 1번 velutina 자리와 같아 마지막 층까지 그대로 옮겨짐: Transferred 349/349 [확실 — 모의 실행 기록])
- 학습: YOLOv5s, 640, 100 epoch(patience 20), freeze 10, VespAI `yolov5s-all-data.pt`에서 시작
- 사진 장수·표본 수·mAP 숫자: 미기록 (승준 "성적 좋음"으로만 확인) → 다음에 9번 칸 숫자 기록할 것

## 4. 해석과 한계
- [가능성 높음] 놓친 16 %는 카메라 흔들림 때문 (승준 관찰). 트랩 카메라는 고정이라 더 오를 것 → **고정 카메라로 다시 재야 확실**
- [확실] 아직 안 본 것: 꿀벌·다른 곤충을 말벌로 착각하는지 (`other` 시험 영상 없음)
- [가능성 높음] 시험 표본이 학습 표본과 같은 개체면 실제보다 점수가 높게 나옴 — 표본 수가 늘면 표본별로 나눠 다시 잴 것
- 웹캠 조건임. 트랩 카메라 Camera Module 3 (렌즈 → 격자 153.5 mm, 인터페이스 정의서)와 화각·화질이 다름 → CM3 오면 같은 노트북으로 다시 시험

## 5. 정해야 할 것
1. **(서현·승준) 인터페이스 정의서 `species` 값**: 지금 정의는 `velutina / crabro / other` (VespAI 클래스 1/0). 새 모델은 `crabro`가 없음 → `velutina / other` 둘로 바꿀지
2. **(승준) Pi 5에서 어떻게 돌릴지**: Pi 5 CPU로 YOLOv5s 그대로 vs AI HAT+(Hailo)용 `.hef` 변환 — 속도 실측 필요
